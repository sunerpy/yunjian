# 学习、字典与拼音设计

本文定义云笺的背诵复习方式、内置字典与拼音开关。它是一份实现前设计，不表示这些界面和数据结构
已经落地。设计保留现有 FSRS 调度器和语音诚实边界，重点解决三个问题：长诗怎样拆成可记忆单元，
每日任务怎样不被积压压垮，以及遇到生僻字、破读和多音字时怎样给出有出处且不过度断言的帮助。

## 结论先行

1. **不换 FSRS。** 云笺继续使用现有 FSRS-6 参数、四级自评和稳定 `stable_id` 历史；新设计在
   FSRS 外解决拆卡、当日内再学习、每日预算和积压治理。
2. **长诗不按整首排程。** 整首是汇总对象，联片是 FSRS 卡，音步是示范与练习单元。四行且正文
   不超过 32 字的短诗可以退化成一张整诗联片卡。
3. **吟诵是默认学习路径。** 依次为音步示范、karaoke 跟读、主动回忆。语音只反馈是否开口、
   停顿和相对节奏；绝不自动判断字准或选择 FSRS 等级。
4. **先清到期，再引入新卡。** 每日计划按时间预算装箱；到期任务超过预算时暂停新卡，同时把积压
   数量、预计耗时和七日压力直接显示出来，不用“今日完成”掩盖未清债务。
5. **字典 v1 是韵书事实面板，不是现代辞书。** 它只展示随仓 `rhyme`、`variant_map` 与有定位
   依据的破读事实。现代辞书释义永久排除，不预留导入入口。
6. **拼音与平仄是两个独立开关。** 有证据的破读优先；不能确定时并列展示候选并写“此处读音
   存疑”，绝不从韵部猜出现代拼音。

## 现状、证据与边界

### 为什么不是再造一种记忆算法

FSRS 与墨墨使用的 DHP 系方法同源。已有对照材料没有证明 MMX-6 在线效率更高，反而观察到活跃和
完成留存下降；现有实际保持率约 75%，也低于 85% 的运营目标。这里更直接的问题不是“公式不够新”，
而是用户每天收到多少任务、欠了多少任务、长诗是否被当成不可完成的大卡，以及失败后能否在当天
重新站稳。因此本设计不建议替换 FSRS。

当前实现也决定了兼容方式：`Scheduler::review_at` 在首评时把 `None` 交给 FSRS，随后保存
`stability`、`difficulty`、`due_day` 和四级等级；没有“把客观特征直接写成初始 difficulty”的
接口。冷启动特征因此只能用于新卡排序、耗时预估和风险提示，不能冒充 FSRS 记忆难度。

### 已有能力

- 调度器使用 `Again` / `Hard` / `Good` / `Easy`，历史按稳定作品标识保存；内容摘要变化不会清空
  历史。
- 打字路径有确定性归一化、五类 `AlignOp` 和严格/宽松准确率；近音只宽容替换，不宽容漏字和增字。
- 语音路径已有 `FootMark` 时间戳、逐句会话与三项节奏反馈，结束时等待用户自选等级。
- `pinyin` 依赖能返回一个字的全部拼音候选；`Poyin` 能按“字 + 句中语境”找到明确破读覆写。
- 语料已有 `rhyme`、`variant_map`、`tag`、`poem_tag` 表，但当前分发工件的 `tag` 和
  `poem_tag` 都是 0 行。

### 不做什么

- 不设计语音自动评分，不从 ASR 转写推导字准、完整度或 FSRS 等级。
- 不替换 FSRS，不把冷启动启发式写入 FSRS 的 `difficulty`。
- 不收录或转录任何现代辞书释义，也不设计一个以后可以接入现代辞书的 provider 插槽。
- 不用 AI 生成图片。若产品其他位置以后出现 AI 生成的文字解释，它也不得写进字典主数据，必须在
  独立区域标出模型和“未经人工审校”。
- 不在尚无数据时宣称标签可用，也不编造 1815 个韵书候选里有多少能被唯一确定。

## 学习对象与掌握度

### 三层对象

| 层级 | 作用                               | 是否进入 FSRS | 稳定身份                                      |
| ---- | ---------------------------------- | ------------- | --------------------------------------------- |
| 整首 | 展示总进度、完整背诵检查和统计汇总 | 否            | `poem.stable_id`                              |
| 联片 | 独立回忆、评级与到期排程           | 是            | `poem_id + segmentation_version + line_range` |
| 音步 | 示范播放、karaoke 高亮、局部重复   | 否            | `chunk_id + foot_index`                       |

“联片”按语料中的韵律行确定：相邻两行组成一片；末尾若剩一行，并入前一片。四行且正文内容字数不
超过 32 的作品作为一个联片，避免把绝句机械拆碎。词、曲和不规则文体仍按现有韵律行切分，不按屏幕
换行切分。分段算法必须版本化；同一版本重建后，联片身份和边界逐字节稳定。

整首不直接排程，避免一首长诗的一次失败同时制造一个昂贵到期项和一个模糊等级。音步也不排程，
因为它是动作支架，不应产生几十张零碎卡。只有联片承载一次可独立回答的记忆判断。

### 掌握度不做平均数粉饰

作品页同时展示：

- `已建立`：完成过首次独立回忆的联片数 / 总联片数；
- `到期`：当前到期或逾期的联片数；
- `薄弱点`：最近一次为 `Again` / `Hard` 的联片；
- `完整背诵`：所有联片都建立后，最近一次不带文字提示的整首检查结果。

整首只在**每一片都已建立且没有逾期联片**时显示“当前稳固”。不能用各片平均分抵消一片完全不会。
完整背诵检查是汇总事件，不创建第二套 FSRS 卡，也不改变各联片到期日；用户仍逐片确认等级，避免把
整首的一次主观感觉覆盖细粒度历史。

## 默认学习路径

每个新联片走同一条渐隐支架，用户可提前跳到主动回忆，但系统不默认跳过理解和节奏：

1. **看与查。** 显示原文；按需打开拼音、平仄或字典。新出现的存疑读音先显式暴露，不在播放时
   静默猜测。
2. **音步示范。** 按 `FootMark` 播放并高亮音步；无语音能力时保留视觉分组和手动推进。
3. **karaoke 跟读。** 高亮跟随示范音移动。播放与录音不重叠；用户复诵后只收到活动、停顿、相对
   节奏反馈。
4. **首字提示。** 每行只留首字，要求补全联片。
5. **遮罩回忆。** 使用现有 `Cloze` / `FirstChar` / `Masked` 练习逐步减少提示。
6. **主动回忆。** 无正文提示完成打字或自述背诵；这一次才产生正式 FSRS 等级。

字典打开、拼音打开和重复示范都是学习支架，不算失败，也不直接降低等级。系统可记录这些行为用于
评估难度特征，但正式等级只来自打字映射或用户选择。

## FSRS 与当日内再学习

### 正式复习只提交一次

每个到期联片的第一次独立回答是正式复习：立即调用现有调度器提交 `Again` / `Hard` / `Good` /
`Easy`。语音路径总由用户选择；打字路径可以给出现有确定性映射的建议，用户可以改选。

`Again` 或 `Hard` 会额外进入**当日内再学习队列**：

- 第一次在正式复习后 10 分钟出现；
- 通过后在 1 小时后再出现一次；
- 再次失败则从失败时刻重新安排 10 分钟，直到通过或当天结束；
- 跨过本地日界仍未完成时，显示为未完成再学习，不擅自制造一条新的 FSRS 复习记录。

这些 10 分钟 / 1 小时尝试只写练习事件，**不再次调用 `Scheduler::review`，不推进 `due_day`**。
这样既能在遗忘后及时重建，又不会把同一天的密集点击伪装成多天记忆证据。新联片完成首次主动回忆
后同样只提交一次正式等级；此前的示范、跟读和遮罩练习都不喂给 FSRS。

### 失败后的最短恢复路径

再学习不把用户送回整首开头。它先重播失败联片的音步，再做首字提示，最后做一次无提示回忆。若只
错一个音步，界面可从该音步开始练，但最终通过条件仍是按正确顺序完成整个联片。

## 每日预算、积压与压力可见性

### 用时间预算而不是虚假的固定卡数

首次运行建议 15 分钟每日预算，用户可修改。每个联片的预计耗时取该用户同类联片实际耗时的指数
移动平均；样本不足时用正文内容字数和是否首次学习估算。估算只负责装箱与展示，不影响 FSRS。

每日队列按以下顺序装入预算：

1. 当日内 10 分钟 / 1 小时再学习；
2. 逾期联片，逾期更久者优先；
3. 今日到期联片；
4. 仍有预算时才加入新联片，并服从用户的新卡上限。

若前三项已经占满预算，当天新卡数为 0。系统不把未装入计划的到期卡隐藏掉，而是把它们列为
“积压”；用户可以主动加时，但默认按钮只承诺完成计划内工作。

### 首页必须显示的压力信息

- 今日计划：卡数和预计分钟数；
- 到期总量：计划内 / 未装入计划；
- 逾期积压：联片数、最老逾期天数和预计清理时间；
- 未来七日：按当前 FSRS 到期日聚合的预计分钟数；
- 观察保持率：过去 30 天到期复习中非 `Again` 的比例及样本量；
- 目标保持率：运营目标 85%，与观察值并列而非替换观察值。

现有调度代码使用 `DESIRED_RETENTION = 0.9`，这是 FSRS 计算间隔时的模型目标；首页的 85% 是真实
复习结果的运营目标。二者必须用不同名称展示，不能把模型参数当成已实现的真实保持率。样本不足时
只显示“数据不足（n=…）”，不外推百分比。

## 冷启动难度

### 特征只做负担估计，不注入 FSRS

候选特征全部能在本地、离线、确定性计算：

| 特征            | 初始计算                                         | 启用前验证                                        |
| --------------- | ------------------------------------------------ | ------------------------------------------------- |
| 字数            | `content_chars` 数量                             | 与首次学习耗时、首周 `Again` 率做分箱和单调性检验 |
| 生僻字比例      | 按全语料字频标出低频字占比                       | 检查是否独立解释字典打开率、耗时和首周失败        |
| 破读/多音候选数 | 正文与 `poyin.tsv`、`polyphone_index.tsv` 的交集 | 检查候选数与读音存疑、查字和失败的关系            |
| 异体字数        | 正文命中 `variant_map` 的数量                    | 检查是否增加输入纠正、查字和耗时                  |
| 句式规整度      | 韵律行长度的离散程度及可切出的音步数             | 检查同字数下是否影响学习耗时和顺序错误            |
| 典故/主题标签   | `poem_tag` 提供的标签                            | 当前表为空，**禁用**；重建语料且验证覆盖后再评估  |

首版只有字数参与耗时回退估算，因为它的定义和观测最直接；其余特征先记录、不排序。每个候选必须
在预先冻结的时间窗和指标上显示稳定方向，并在留出作品上改善耗时估计，才可单独启用。不得为了得到
一个“难度分”先拍脑袋给权重。

`polyphone_index.tsv` 当前物理文件 1843 行，其中注释声明 1815 个基本区数据候选；尚未计算有多少
能结合语境唯一确定。界面、指标和文档在完成可复现实测前都不得给出唯一确定率。

## 打字评分与顺序错误

当前 `AlignOp::ReRecitation` 表示回到已正确区间后连续重读，不能完整表达把两行交换、把后句提前或
整块倒序。因此不能把“回读次数”当成全部顺序错误。

打字路径新增一个独立、确定性的顺序层，且**只用于打字，不进入语音路径**：

1. 用与联片相同的韵律行/音步切分，把参考文本编码为稳定单元序列；
2. 在用户答案中匹配完整单元，求参考序列与命中序列的最长公共子序列（LCS）；
3. `ordered_coverage = LCS 长度 / 参考单元数`；完整出现却落在 LCS 外的单元记为移动，不和漏字混为
   一类；
4. 建议等级使用 `min(现有 completeness, ordered_coverage)` 参与现有完整度阈值，检测到移动时
   禁止建议 `Easy`；严格准确率仍按原文字级结果显示。

这套映射在启用前必须先用黄金用例证明：正确顺序不降分、交换相邻两行能检出、整块倒序比一次局部
回读更重、重复正确行仍是 `ReRecitation` 而不是移动；再用匿名本地回放比较“建议等级被用户改选”的
比例。验证不过时只展示顺序提示，不改变等级。

## 吟诵和语音边界

吟诵作为默认路径的依据是已有材料中唱诗长期留存 100%、朗诵 32% 的明显差异。这个结果支持把
节奏和旋律支架放到学习入口，但不支持机器判断某人的发音是否标准。

实现复用现有 `FootMark { start_sample, end_sample }`：示范播放时按样本区间移动高亮，用户可以点击
某个音步重复。录音必须在示范停止后开始，不能让麦克风听到扬声器并产生虚假反馈。

语音契约继续只有：

- `guided_practice`：示范、复诵以及开口/停顿/相对节奏反馈；
- `coverage_advisory`：只有独立 KWS 实验通过冻结门槛后才可能开放的粗粒度覆盖提示。

任何模式都不提供逐字读音评级、漏字列表或自动 FSRS 等级。文言 ASR 当前实测 CER 为 77.01%，
不能作为对齐评分输入。语音、模型或权限不可用时，路径降级为视觉音步 + 手动节拍 + 打字练习，
学习和复习不能被语音能力阻断。

## 内置字典

### v1 条目

点击正文单字打开就地面板，按以下顺序展示存在的数据：

1. 字形，以及 `variant_map` 中可验证的异体/归一字关系；
2. 当前句的拼音状态：有据破读、通用候选或“此处读音存疑”；
3. 《平水韵》《词林正韵》中的 `rhyme_book`、`tone_raw`、`rhyme_group`；同字多条全部展示，
   不替用户选择；
4. 若命中 `poyin.tsv`，展示 `confidence` 与完整 `evidence`；
5. 数据边界说明：“韵书记录声部和韵部，不等于现代释义，也不能单独推出当前拼音。”

`rhyme` 表只有 `rhyme_book`、`rhyme_group`、`tone`、`tone_raw`、`character`，没有现代拼音或
释义字段。v1 只消费这些已有事实，因此不新增许可风险，也不伪装成综合汉语词典。

### 永久来源规则

现代辞书释义永久排除，既不随包存储，也不提供在线查询或以后接 provider 的扩展口。未来若补充
公有领域字书，只能作为新的、具名的数据资产进入 `corpus/sources.toml`，通过 `verify-sources`，
并让每条记录携带非空 `source_locator` 和卷次/部次/页码定位符；来源不明或无法定位的条目直接拒绝。

AI 文字若用于独立的学习解释，必须与字典事实分区，不参与搜索和读音裁决，不写回语料；每段都显示
模型标识和“未经人工审校”。本设计不需要也不允许 AI 生成图片。

## 拼音与平仄开关

### 解析优先级

整首加载时一次性解析每个内容字，按以下规则生成注音，不逐字发查询：

1. 当前句命中 `Poyin::reading` 且 `confidence` 为 `rhyme_attested` 或 `tone_split`：显示该带调
   拼音和依据标记；具体语境行优先于 `*` 行。
2. 未命中覆写时，从现有 `ToPinyinMulti` 取得全部候选。只有一个候选才直接显示，并标为“通用
   拼音”，不声称是古典语境裁决。
3. 有多个候选且没有破读证据时，并列显示候选；正文紧凑模式显示一个存疑标记，点击后看到
   `xíng / háng / …` 和“此处读音存疑”。
4. 没有拼音数据时不造占位读音，只显示“暂无注音”。

`engine_default` 行明确表示不覆写，不能提升为“已有证据的读音”。`rhyme` 的兼收记录只能帮助解释
为什么存疑，不能从韵部直接猜出现代拼音。`data/poyin.tsv` 当前物理 117 行，覆盖边界是
`reading_roster.tsv` 的 22 首；表外不得宣称破读覆盖完整。斜 `xiá`、衰 `cuī`、骑 `jì` 是现有
有据黄金例。

### 排版规则

拼音和“平仄/韵部”分别持久化开关状态，互不暗开：

- 横排时拼音用字上方 ruby 层；平仄用基线下方的小型标记或行末韵脚标记；
- 竖排时拼音放在字列外侧，平仄放在字格内侧/行末；两者不得争用同一侧；
- 两个开关同时打开时保持正文行距可读，存疑标记跟随拼音层，韵脚标记跟随平仄层；
- 进入无提示主动回忆时默认隐藏两层，用户主动揭示会记录为支架使用，但不自动判错。

长诗按整首批量预取和解析；面板打开只读取内存结果。切换开关不得触发逐字数据库查询、网络请求或
音频模型加载。

## 数据契约与缓存

设计需要下列逻辑记录；名称是契约草案，不代表数据库已迁移：

| 记录                | 必要字段                                                                   | 说明                             |
| ------------------- | -------------------------------------------------------------------------- | -------------------------------- |
| `learning_chunk`    | `chunk_id`, `poem_id`, `segmentation_version`, `line_start`, `line_end`    | 联片稳定边界                     |
| `practice_event`    | `chunk_id`, `kind`, `started_at`, `duration_ms`, `scaffold_used`, `result` | 当日内练习，不等于 FSRS 日志     |
| `whole_poem_check`  | `poem_id`, `checked_at`, `result`, `weak_chunk_ids`                        | 汇总事件，不排程                 |
| `annotation_bundle` | `poem_id`, `content_hash`, `lexicon_hash`, `items`                         | 整首拼音、存疑与韵书事实批量结果 |

FSRS 状态继续由现有 `review_state` / `review_log` 持有。联片 ID 必须稳定且与整首 ID 有显式父子关系；
分段版本变化时先生成迁移报告，不能静默丢弃历史。注音缓存键至少包含作品内容摘要和破读词表摘要，
任一变化即整首失效重建。

本地事件默认只服务本机统计。若以后设计同步或遥测，必须另行说明数据最小化和用户同意；本方案不把
诗文输入、录音或学习历史发送到第三方。

## 指标、实验与验收

### 结果指标

- 30 天观察保持率及样本量，目标 85%，当前基线约 75%；
- 每日计划完成率与“积压仍存在但计划显示完成”的误导事件数（目标为 0）；
- 逾期积压联片数和预计清理天数；
- 新联片首次建立耗时、首周 `Again` 率；
- 整首检查通过率，以及最弱联片分布；
- 建议等级被用户改选率，按普通错误和顺序错误分层；
- 拼音状态覆盖：有据破读 / 单候选通用拼音 / 多候选存疑 / 无数据，必须给绝对数量和分母。

### 必须通过的验收门

1. **调度守恒：** 当日内再学习不会增加 `review_log`，不会改变 FSRS `due_day`。
2. **拆分稳定：** 同一语料、同一分段版本生成完全相同的联片 ID；短诗和末尾孤行有黄金测试。
3. **不隐藏积压：** 任意预算下，`计划内 + 未装入计划 = 到期总量`。
4. **顺序检出：** 正序、邻行交换、块倒序、重复和漏行分别命中预期类别；语音类型不能调用该评分。
5. **读音诚实：** 三个黄金破读命中；`engine_default` 不覆写；多候选显示存疑；不得从 `rhyme`
   单独生成拼音。
6. **来源门禁：** 新字书资产缺许可、摘要或定位符时构建失败；现代辞书 fixture 应被拒绝。
7. **性能：** 长诗详情只做一次批量注音/韵书查询；切换开关不增加查询次数。
8. **可访问性：** 颜色不是平仄、存疑或到期状态的唯一编码；ruby 和竖排侧注可被辅助技术按正文后
   注释顺序读取。

任何保持率或效率实验都先冻结时间窗、样本纳入规则和主要指标。不能只报“每天少了几张卡”，因为
减少任务也可能以遗忘为代价；必须同时报告保持率、完成率和积压。

## 分期实施

### Phase 1：先让负担可控

- 实现确定性联片身份、整首汇总、每日分钟预算和积压面板；
- 保持现有 FSRS 参数与评级接口不变；
- 增加 10 分钟 / 1 小时练习队列，但不写 FSRS 复习日志；
- 只用字数做冷启动耗时回退，其余特征仅记录。

### Phase 2：完成默认学习路径

- 把 `FootMark` 接到音步示范与 karaoke 高亮；
- 完成首字、遮罩、主动回忆的支架渐隐；
- 语音失败完整降级到视觉节奏和打字，用户自选等级边界不变；
- 上线打字顺序提示；只有黄金测试和改选率验证通过后才影响建议等级。

### Phase 3：上线字典与双开关

- 批量组合 `Poyin`、`ToPinyinMulti`、`rhyme`、`variant_map`；
- 上线横排 ruby、竖排侧注以及独立平仄层；
- 展示来源、置信度和存疑状态，不上线现代释义；
- 实测并公布四档拼音状态的绝对覆盖，仍不把候选数写成唯一确定数。

### Phase 4：校准而不是重写算法

- 用真实本地事件逐项验证冷启动特征；
- 比较预算与积压策略对 30 天保持率、完成率和活跃的共同影响；
- 只有证据显示某一特征改善负担估计时才启用它，不借机替换 FSRS；
- `tag` / `poem_tag` 在语料工件有真实覆盖前始终禁用。
