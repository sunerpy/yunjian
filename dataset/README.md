# 云笺随包 AI 赏析数据集

本目录里的 `appreciations.json` 是随云笺一同分发的**预生成 AI 赏析**数据集。
它不是学术成果，也不是任何人的赏析文章。

## 请先读这一段：这些文本的可靠性

- **内容由 AI 生成（AI-generated）。** 每一条都是模型的输出，不是人写的。
- **未经领域专家审校。** 数据集里每条记录的 `reviewed` 字段恒为 `false`，
  本项目也**没有**产生「已审校」记录的途径。
- **可能包含编造的典故、错置的作者归属或事实性错误。** 这不是保守措辞：生成模型在
  古典诗词这个题材上编造典故与错置作者是已知的、反复出现的失效模式。提示词把语料已知
  的事实（作者、朝代、词牌、平仄、韵部、公有领域历代集评）作为事实块交给模型，并要求
  它不得断言事实块之外的典故与归属——但那是缓解措施，不是保证。
- **未经独立核实不得依赖。** 请勿把这里的任何一句话当作考据结论、教学材料或引用来源。

界面上这些文本一律标注为「**AI 赏析**」，绝不写成「赏析」，也与带出处的历代集评在
视觉上分开呈现。

## 它为什么用开放权重模型生成

随包数据集由**可下载权重**（MIT 许可的 DeepSeek 权重、Qwen 或同等）生成，
**不使用任何闭源 API**。

理由是授权链而不是性能偏好。逐条读过条款后：Anthropic 的商用条款把 Output 的权利
让给客户，但禁止用其服务构建竞品、包括训练竞争模型；OpenAI 的对应条款未能核实
（站点返回 403，需要人工阅读）；DeepSeek 的条款完全未核实。三条里两条是未知，
而下载下来的权重不附带任何限制「输出如何再分发」的 API 条款——于是这条不确定性
被绕开了，不是被赌掉了。

这条约束由代码强制而不是靠自觉：
`cargo run -p xtask -- pregenerate` 在生成任何一条记录**之前**校验权重许可与运行时，
把它配成闭源 API 供应商会让命令中止并点明开放权重要求。

## 下游使用条件

**不得将本数据集用于训练竞争的 AI 模型**（do not use it to train competing models）。
这条来自上游权重与服务条款里同类的限制，向下游传递。使用本数据集即接受该条件。

代码按 MIT 授权。语料原文是公有领域文本，逐资产的许可判定在 `corpus/sources.toml`。
本数据集里的赏析文本是 AI 输出，与两者都不是同一类内容，请按本文件的条件对待。

## 用户自己生成的赏析永远不在这里

你用自己的 API key 生成的赏析存在本机的 `appreciation_cache` 表里，是**你的** Output。
它永远不会被收进这份数据集：预生成路径拒绝读取那张表（`ensure_readable_table`
对它硬失败），续跑时也只按随包表跳过已完成的作品。

## 覆盖范围

v1 **显式声明**只覆盖名篇集，不尝试全语料：

| 选本       | 说明                   |
| ---------- | ---------------------- |
| 唐诗三百首 | 清 蘅塘退士编          |
| 宋词三百首 | 近人朱祖谋编           |
| 千家诗     | 通行本                 |
| 古诗文名篇 | 通行选本与教材共同收录 |

理由是全语料 47 万首里绝大多数没有人会去读赏析，逐首生成既让成本失控也让工件体积
失控。覆盖范围写在 `appreciations.manifest.json` 的 `coverage_tags` 里，扩大它必须是
一次显式改动。

## 文件

| 文件                          | 内容                                                           |
| ----------------------------- | -------------------------------------------------------------- |
| `appreciations.json`          | 记录数组。顶层是数组而不是对象，元数据全在清单里。             |
| `appreciations.json.sha256`   | 上一项的 SHA-256，格式与 `sha256sum` 可互校。                  |
| `appreciations.manifest.json` | 模板版本、覆盖范围、筛选途径、模型与许可、是否真的执行了推理。 |

每条记录的字段：

| 字段                                   | 含义                                                                                                      |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `stable_id`                            | 作品的稳定标识。**键**。刻意不是 `content_hash`——上游文本修正会换掉后者，键在它上面的记录会当场变成孤儿。 |
| `title` / `author` / `anthology_tags`  | 人工复核用，不参与查找。                                                                                  |
| `model` / `model_license` / `provider` | 生成溯源。`model_license` 必在 `{MIT, Apache-2.0}` 内。                                                   |
| `generated_at`                         | 生成完成时的 Unix 秒数。                                                                                  |
| `template_version`                     | 提示词模板 semver。它进入缓存键，因此改提示词不会静默供旧文本。                                           |
| `grounding_digest`                     | 生成时事实块的 BLAKE3 摘要。语料修正后它对不上，那条记录会被标 `stale` 并落到重新生成。                   |
| `reviewed`                             | 恒为 `false`。                                                                                            |
| `text`                                 | 赏析正文。                                                                                                |

## 清单里的 `generation_executed`

如果它是 `false`，说明那一次运行**没有执行任何推理**：管道、门禁与溯源字段照常校验，
但每条 `text` 都是 `<<未生成：本条不是模型输出，需开放权重模型推理>>` 这个显式标记，
`not_executed_reason` 写明原因。这种产物**不是模型输出，不得当成赏析发布**。

反过来也被强制：声明已执行推理却带着未生成标记的记录会被拒绝。两个方向都拦住，
所以「产物看起来像真跑过」这件事没法在结构上蒙过去。
